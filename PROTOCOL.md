# Протокол моста tbox-proxy (3.0)

Мост — это один процесс-**хост**, который владеет UDP-портом и общается с TBox, и любое число
**клиентов**, которые подключаются к хосту по локальному TCP. Хостом становится первое
приложение с библиотекой, которое не нашло работающий мост.

```
TBox 192.168.225.1:50047  ⇄  UDP :11048  [хост: TBoxBridgeService]  ⇄  TCP 127.0.0.1:1104 (1.x / 2.x)
                                                                    ⇄  TCP 127.0.0.1:1105 (3.x)
```

## Порты

| Порт | Кто подключается | Формат |
|------|------------------|--------|
| UDP 11048 | хост ⇄ TBox | пакеты TBox `8E 5D …` без обёртки |
| TCP 1104 | клиенты 1.x и 2.x | `LEGACY_V1` или `TYPED_V2`, определяется автоматически |
| TCP 1105 | клиенты 3.x | `V3` с рукопожатием |

Оба TCP-порта слушают только `127.0.0.1`. Порт 1104 обязателен: если его занять не удалось,
мост не стартует (`TCP_SERVER_ERROR`). Порт 1105 необязателен: без него старые клиенты
продолжают работать, а клиенты 3.x уходят на 1104 как на старый хост.

## Форматы кадров

Все целые числа — big-endian.

| Формат | Версии | Кадр |
|--------|--------|------|
| `LEGACY_V1` | 1.0.x – 2.0.0 | `[int32 len][payload]` |
| `TYPED_V2` | 2.1.x | `[int32 len][u8 type][payload]`, `len` включает байт `type` |
| `V3` | 3.x | как `TYPED_V2`, плюс типы рукопожатия |

`len` должен быть в диапазоне 1…65536, иначе соединение закрывается как повреждённое.

### Типы кадров

| type | Имя | Направление | Payload |
|------|-----|-------------|---------|
| `0x01` | DATA | оба | пакет TBox (`8E 5D …`) |
| `0x02` | STATUS | хост → клиент | `[u8 ordinal][u16 msgLen][msg UTF-8][u16 detLen][details UTF-8]` |
| `0x10` | HELLO | клиент → хост, только 1105 | `[u8 protocolVersion][str clientPackage][str libraryVersion]` |
| `0x11` | HOST_INFO | хост → клиент, только 1105 | `[u8 protocolVersion][str hostPackage][str libraryVersion][u8 flags][str networkInterface]` |

`str` = `[u16 длина][UTF-8]`. В `flags` бит 0 означает «UDP-сокет привязан к сети TBox».
Лишние байты в конце HELLO и HOST_INFO игнорируются, поэтому следующие версии могут
дописывать поля в конец, не повышая `protocolVersion`.

`ordinal` в STATUS — порядковый номер `TBoxStatusType`. Новые значения добавляются только в
конец перечисления.

## Рукопожатие v3 (порт 1105)

1. Клиент подключается и первым кадром шлёт HELLO.
2. Хост отвечает HOST_INFO и начинает слать клиенту DATA и все STATUS.
3. Если первый кадр — не HELLO, хост закрывает соединение.
4. При смене сети TBox (например, пересоздан `usb0`) хост повторно рассылает HOST_INFO
   всем клиентам v3.

Клиент ждёт HOST_INFO 1,5 с, иначе считает, что v3-хоста нет.

## Совместимость

### Новый хост (3.x), старые клиенты (порт 1104)

- Каждый клиент на 1104 до первого своего кадра считается `LEGACY_V1`.
- По первому кадру клиента хост определяет его формат:
  - `01 8E 5D …` → `TYPED_V2` (клиент 2.1.x);
  - всё остальное → `LEGACY_V1`.
- Клиенты `LEGACY_V1` получают только данные. Клиенты `TYPED_V2` получают данные и
  статусы с `ordinal` ≤ `LOG` (12); статусы 3.x им не отправляются, потому что 2.1.x их не знает.
- **Ограничение:** клиент 2.1.x, который ничего не отправляет, так и остаётся `LEGACY_V1` и
  получает кадры без байта типа. Для 2.1.x это выглядит как кадры неизвестного типа. Как только
  клиент отправит первую команду, формат переключится.

### Старый хост (1.x / 2.x), новый клиент

- Порт 1105 не отвечает, клиент 3.x подключается к 1104.
- Формат определяется по первому кадру от хоста:
  - `8E 5D …` → `LEGACY_V1`;
  - `01 8E 5D …` или первый байт `02` → `TYPED_V2`.
- Если хост молчит 1 с, а клиенту нужно что-то отправить, используется `LEGACY_V1`.
- Клиент выдаёт статус `LEGACY_HOST`, `getHostInfo()` содержит только `protocol`.
- **Ограничения:**
  - UDP-сокет старого хоста не привязан к сети TBox. На ГУ Android 10 (Adayo) при включённом
    Wi-Fi исходящие пакеты уходят в `wlan0`: данные от TBox приходят, а команды до TBox не
    доходят (подтверждено на ГУ, см. ниже).
  - Статусов 3.x (`NETWORK_BOUND`, `TBOX_SILENT` и т.д.) нет.
  - Новый клиент не может забрать роль хоста, пока старый хост жив.
- Когда старый хост завершается, клиент 3.x через 1–1,5 с поднимает собственный мост v3.

### Клиенты 1.0.x не переподключаются

В 1.0.x нет повторного подключения: если хост завершился, клиент 1.0.x остаётся без данных до
своего перезапуска. Хост 3.x на это повлиять не может, поэтому хост стоит держать живым и не
перезапускать без необходимости.

## Сеть TBox

На ГУ Android 10 (Adayo) при включённом Wi-Fi правило маршрутизации по умолчанию отправляет
трафик к `192.168.225.1` в `wlan0`, а не в `usb0`. Хост 3.x:

1. через `ConnectivityManager.registerNetworkCallback` ищет сеть, у которой есть IPv4-адрес в
   подсети TBox (`remoteAddress` + длина префикса из `LinkProperties`);
2. привязывает к ней UDP-сокет через `Network.bindSocket` (root не нужен);
3. при пропаже или смене сети пересоздаёт сокет и сообщает `NETWORK_BOUND` / `NETWORK_UNBOUND`.

На ГУ Android 9 трафик и так идёт в `usb0`, привязка ничего не меняет. Отключить привязку можно
параметром `TBoxClient(bindToTBoxNetwork = false)`.

## Сторож (watchdog)

- Сразу после старта хост шлёт TBox пробный запрос: CRT `0x12`, payload `00 00 01 05`.
- Если от TBox нет данных 10 с, клиентам один раз уходит `TBOX_SILENT`
  (клиент 3.x вызывает `onConnectionChanged(false)`).
- Пока TBox молчит, пробный запрос повторяется каждые 10 с; после трёх безответных
  запросов UDP-сокет пересоздаётся.
- Когда данные снова пошли, уходит `TBOX_RESPONDING`, и клиент вызывает
  `onConnectionChanged(true)`.
- В отличие от 2.1.0 мост при молчании TBox **не** останавливается, поэтому клиенты 1.0.x
  не теряют соединение.

## Отладка

```
adb shell setprop log.tag.TBoxBridge VERBOSE   # лог каждого UDP-пакета
adb logcat -s TBoxBridge
```

Без этого свойства хост пишет в logcat только INFO и выше и не форматирует пакеты.

Скрипты в `tools/` (скопировать в `/data/local/tmp`, запускать через `sh`):

- `ports.sh` — кто владеет UDP 11048 и TCP 1104/1105, состояние соединений;
- `inode_owner.sh <inode>` — процесс-владелец сокета;
- `udp_counters.sh add|show|del` — счётчики iptables для пакетов к TBox по интерфейсам
  (`wlan0` / `usb0`), нужен root.

| Сценарий | Android 9 (Wi-Fi вкл.) | Android 10 (Wi-Fi вкл.) |
|----------|------------------------|-------------------------|
| Хост 3.0 + клиенты 1.0.4, 2.1.0 и 3.0 | данные и ответы на команды у всех | то же; UDP идёт через `usb0`, через `wlan0` — 0 пакетов |
| Хост 3.0 + реальный клиент 1.0.x (`ras.dashing.tbox.launcher`) | подключён, получает данные | — |
| Хост 2.1.0 + клиент 3.0 | `LEGACY_HOST`/`TYPED_V2`, ответы на команды приходят | `LEGACY_HOST`/`TYPED_V2`, данные приходят, команды уходят в `wlan0` без ответа |
| Хост 1.0.4 + клиент 3.0 | — | `LEGACY_HOST`/`LEGACY_V1`, данные приходят |
| Старый хост завершился | клиент 3.0 стал хостом v3 через 1,2 с, привязан к `usb0` | — |
