# Changelog

## 3.0.0

Совместим с приложениями на 1.x и 2.x в обе стороны: новый хост обслуживает старых клиентов,
новый клиент работает со старым хостом. Подробности — в [PROTOCOL.md](PROTOCOL.md).

### Новое

- Порт v3 `1105` с рукопожатием HELLO → HOST_INFO. Порт `1104` остаётся для клиентов 1.x/2.x;
  формат каждого клиента (1.x или 2.1) определяется по его первому кадру.
- Клиент 3.x работает со старым хостом: определяет его формат и выдаёт статус `LEGACY_HOST`.
- UDP-сокет хоста привязывается к сети TBox (`Network.bindSocket`). Исправляет отсутствие связи
  с TBox на ГУ Android 10 при включённом Wi-Fi. Параметр `bindToTBoxNetwork`.
- Новые статусы (в конце `TBoxStatusType`): `NETWORK_BOUND`, `NETWORK_UNBOUND`, `TBOX_SILENT`,
  `TBOX_RESPONDING`, `LEGACY_HOST`. Клиентам 2.1.x они не отправляются.
- `TBoxClient.getHostInfo()`, `getWireProtocol()`, `TBoxHostInfo`, `TBoxWireProtocol`,
  `TBoxProxyInfo.LIBRARY_VERSION`.
- Сторож больше не останавливает мост при молчании TBox: шлёт пробные запросы, пересоздаёт
  сокет и сообщает `TBOX_SILENT` / `TBOX_RESPONDING`.
- JVM-тесты: кодек, протокол, смешанные клиенты 1.x/2.1/3.x с фейковым TBox, старые хосты.

### Исправлено

- `FrameCodec.decode` сверял длину с `buffer.size`, а не с количеством прочитанных байтов —
  при частичном чтении разбирался мусор.
- Сервер и клиент разбирали только первый кадр из `read()`, остальные ждали следующего чтения.
- Параллельные рассылки писали в один сокет одновременно, и байты кадров могли перемешиваться.
  Теперь у каждого клиента своя очередь и свой писатель; медленный клиент не тормозит остальных.
- `runBlocking` в `TBoxBridgeService.onDestroy` (риск ANR) и в `TcpClient.cleanup` (риск deadlock).
- Неверный приоритет `Log.println` (`ordinal + 2`).
- Каждый DEBUG-лог, включая лог каждого пакета, рассылался всем клиентам статусом. Теперь
  клиентам уходят только INFO и выше, а пакеты логируются только при
  `setprop log.tag.TBoxBridge VERBOSE`.
- Буфер приёма UDP 4096 байт → 65535.
- `START_STICKY` с `null`-интентом поднимал мост без параметров. Теперь `START_NOT_STICKY`.
- Не был указан `foregroundServiceType`, обязательный на Android 14+. Добавлен `specialUse`.
- `TBoxCommand.equals/hashCode` сравнивали `data` по ссылке.
- При неудачном запуске моста клиент не пытался подключиться снова. Теперь повтор через
  1–1,5 с (со случайной задержкой, чтобы клиенты не стартовали мост одновременно).
- `SO_REUSEADDR` на UDP не используется: иначе два хоста могли занять порт 11048 одновременно.

### Изменено

- Из манифеста библиотеки убраны `READ/WRITE_EXTERNAL_STORAGE` (перенесены в demo).
- `TBoxBridgeService` без действия в интенте останавливается.
- Логика моста вынесена в `TBoxBridge` (чистый JVM), сервис только управляет жизненным циклом.

### Известные ограничения

- Клиент 2.1.x, который ничего не отправляет, получает от хоста 3.x кадры формата 1.x.
- Со старым хостом на ГУ Android 10 с включённым Wi-Fi команды до TBox не доходят: сокет
  старого хоста не привязан к `usb0`.
- Клиенты 1.0.x не переподключаются после смерти хоста (ограничение 1.0.x).
- Сохранена особенность `TBoxReceivedMessage`: `tid` = байт 9, `sid` = байт 8.
